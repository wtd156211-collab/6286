# 数值与单位解析（从 0 实现）

起始环境里没有代码：只有这份说明和 `samples/` 下的输入与期望结果，实现要新写。

## 1. 范围

**做什么**：输入每行是运营在表格里自由填写的一格文本，解析成「数值 + 标准单位」；解析不了的拒绝并给出
原因码，拿不准的列出可能含义。

- 交付：可 `import` 的解析库 + 命令行入口（Python 3.13，只用标准库）；`web/` 下的静态页面
  （原生 HTML/CSS/ES module，无构建、无依赖）；测试用 `unittest`。
- 输入一行一格（UTF-8），输出 JSON Lines，逐行对应、顺序敏感。
- 页面逐条列出原文与结果、被拒标红并写明原因、顶部给成功率与拒绝原因分布（详见第 4 节）；
  数值与原因只能取自引擎输出。

**不做**：换算表以外的量纲（面积、体积、速度、温度、货币）、市斤/英寸/华氏度等民间或英制单位、
复合单位（`米/秒`）、科学计数法（`1e3`）、全角数字、中文大写数字（壹/贰/佰/仟）、英文读数；
不做自动纠错与四舍五入（十进制精确算，写法取最短）；不做 CSV/Excel 解析、数据库与网络存储。

## 2. 口径与公式

- 阿拉伯数字：`整数[.小数]`，整数可带千分位、严格三位一组（`1,234,567`）；出现 `,` 但不满足严格分组
  按 `AMBIGUOUS_NUMBER` 拒绝。
- 中文数字：`零一二三四五六七八九十百千万亿` 与 `两`，按节算 `亿×10^8 + 万×10^4 + 个位`；小数用 `点`。
- 倍数后缀：阿拉伯数字后可紧跟或空一格写一个 `万`/`亿`（`1.5万` = 15000）；中文数字自带倍数，不再叠加。
- 不允许正号、科学计数法、多个小数点；`-` 只在数值最前，负值一律拒绝。
- 单位：与数字之间可有 0 个或多个空格，英文缩写大小写不敏感，中文全称与缩写等价；`百分之` 只作前缀，
  接纯数字，不带单位与倍数。
- 区间：`下界 [单位] 连接符 上界 [单位]`，连接符取第一个左右都不为空的 `~`、`～`、`到` 或 `-`
  （`-` 左边为空按负号处理）；两段各自解析，先左后右报错；一端缺单位时继承另一端；量纲不同或上界小于
  下界都拒绝，上下界相等允许。
- 换算：`结果 = 数值 × 倍数 × 单位系数`，单位取该量纲的标准单位；全程十进制精确运算，输出用最短十进制
  （不用科学计数法、不加千分位）；换算后要满足 `0 ≤ v ≤ 10^12`，否则 `OUT_OF_RANGE`。

**单位换算表**

| 量纲 | 标准单位 | 等价写法（系数） |
| --- | --- | --- |
| 长度 | m | `米`/`m` 1；`千米`/`公里`/`km` 1000；`厘米`/`cm` 0.01；`毫米`/`mm` 0.001 |
| 质量 | kg | `千克`/`公斤`/`kg` 1；`克`/`g` 0.001；`吨`/`t` 1000 |
| 时间 | s | `秒`/`s` 1；`分钟`/`min` 60；`小时`/`h` 3600；`天`/`d` 86400 |
| 百分比 | % | `%` 1；`百分之` 1（`50%` 与 `百分之五十` 都出 50 %） |

**歧义写法**（拒绝并列出可能含义，不许挑一个）：`m`/`M` 可能是米（长度）或分钟（时间）；连写的
`数字+米|m|M+一位数字`（`3米2`、`3m2`）可能是 3.2 米（长度）或 3 平方米（面积）。

## 3. 状态机与数据结构

单行按顺序走，哪步失败就带原因码拒绝：① 去首尾空白（半角空格、Tab、全角空格），空 → 空值；② 找连接符，
切成一段或两段；③ 每段先查歧义写法（`3米2` 这类），命中就拒绝并给出可能含义；④ 切「数值 + 单位」，
数值走阿拉伯或中文两条路，单位查换算表，一个写法对应多个量纲（如 `m`）也按歧义拒绝；⑤ 区间两端：
单位继承 → 量纲一致 → 上下界有序；⑥ 换算到标准单位，生成结果对象。

结果写 JSON Lines，键序固定 `line,status,code,candidates,value,unit,normalized`，用不到的键不出现：

- 成功：`{"line":3,"status":"ok","value":3000,"unit":"m","normalized":"3000 m"}`；无量纲时 `unit` 为 `null`；
  区间 `value` 是 `[下界,上界]`，`normalized` 用 `~` 连成 `"1000~2000 m"`。
- 空值：`{"line":7,"status":"empty","code":"EMPTY"}`。
- 拒绝：`{"line":9,"status":"reject","code":"AMBIGUOUS_UNIT","candidates":["m","min"]}`；`candidates` 只随
  `AMBIGUOUS_UNIT` 出现，按字典序列出可能含义（`m`/`min`/`m^2`）。

**原因码**：`EMPTY` 空值（不算拒绝）；`AMBIGUOUS_UNIT` 单位有两种可能；`AMBIGUOUS_NUMBER` 含 `,` 但不满足
严格千分位；`UNPARSEABLE` 其余无法解析（错别字、缺数字、多小数点或单位、正号、科学计数法、全角或大写数字）；
`UNIT_MISMATCH` 区间两端量纲不同；`INVALID_RANGE` 上界小于下界；`OUT_OF_RANGE` 数值为负或超 10^12。

## 4. 输入输出与文件格式

- 输入文件：UTF-8（`\r\n` 也认、BOM 忽略），一行一格；空行与纯空白行是合法输入，末尾换行不算一行。
- 输出文件：UTF-8 JSON Lines，紧凑写法（`,` 与 `:` 后不加空格），每行以 `\n` 结尾；行数与顺序同输入严格
  一一对应，期望文件按字节比对。
- 命令行：仓库根目录执行 `python -m parsebot <输入.txt> <输出.jsonl>`；整批跑完退出码 0（含拒绝行），
  用法错 2，输入不可读 1，日志走 stderr。
- 库入口：`parsebot.parse_line(text)` 返回与结果对象同构的 dict（不含 `line`），命令行与页面都走它。
- 页面：`python -m http.server 8000` 后开 `web/index.html`（`file://` 下 `fetch` 用不了）；结果由引擎写出，
  如 `python -m parsebot samples/inputs/common.txt web/data.jsonl`。必须显示逐条原文与数值、标准单位，被拒行
  标红并写明原因码与候选含义，顶部显示成功率与原因码分布；一次最多渲染 2000 行，可翻页或
  「加载更多」，统计按全量算。

## 5. 性能与验收口径

- 规模：`samples/inputs/scale.txt` 十万条；测试机（Windows + Python 3.13、单进程、4 核 / 8 GB）端到端含读写
  ≤ 30 秒，峰值内存 ≤ 256 MiB；结果流式写出，不许整批先攒在内存里。
- 确定性：同一批输入跑两遍，输出 JSONL 逐字节相同，拒绝集合与原因码也相同。
- 验收逐条：① 按第 4 节跑 `samples/inputs/<case>.txt`，输出与 `samples/expected/<case>.jsonl` 逐字节相同
  （键序、数值写法、原因码、结尾换行都算）；② 十万条在预算内跑完且两遍 sha256 一致；③ 页面四项信息
  （逐条结果、标红拒绝、原因与候选、顶部统计）齐全，数字与引擎输出一致；④ `python -m unittest discover`
  跑通，用例只读 `samples/`；⑤ 只用标准库，无构建步骤、无 CDN，不出现第 1 节「不做」里的行为。

## 6. 样例说明

`samples/inputs/*.txt` 与 `samples/expected/*.jsonl` 同名成对、逐行对应、顺序敏感（比字节）：

| 输入 | 行数 | 覆盖 |
| --- | --- | --- |
| `common.txt` | 20 | 阿拉伯/中文数字、千分位、小数、百分号、缩写与全称、区间 |
| `mixed.txt` | 16 | 中英文混用、大小写、倍数加单位、区间两端不同单位 |
| `ambiguous.txt` | 13 | 短单位两义、歧义逗号、量纲不一致、区间倒序、越界 |
| `invalid.txt` | 14 | 写错、正号、全角数字、大写数字、缺数字多单位、空值与纯空白 |
| `scale.txt` | 100000 | 十万条批量：各类按固定配方混合，压时限与确定性 |

`samples/notes.md` 是现场记录，只描述现象，口径以本说明为准。
